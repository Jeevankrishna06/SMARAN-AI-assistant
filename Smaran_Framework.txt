How Smaran's Wake and Voice Detection System Works
Smaran features a unified, hardware-resilient listening architecture that monitors both physical wake-ups (hand claps) and voice wake-ups (speech commands) simultaneously without locking the audio hardware.

1. Real-time Audio Capture (BufferedMicSource)
Smaran creates a custom wrapper subclassing the standard speech_recognition.Microphone.

Shared Stream Proxy: Instead of opening separate streams (which causes Windows audio driver collisions), it captures a single native hardware stream.
Dual Routing: It constantly feeds raw chunks into a thread-safe Queue for speech recognition, while maintaining a 0.5-second rolling audio buffer in memory for DSP (Digital Signal Processing) clap analysis.
2. Clap Wake Detection (ClapClassifier)
To identify a clap and separate it from background laptop fan hum, mouse clicks, or human speech, the system runs the 0.5s audio buffer through four mathematical filters:

Rise Time (Attack): A clap is an impulsive sound. The classifier tracks the sound's onset; the amplitude must rise from background noise to its peak extremely quickly (under 50 milliseconds).
Decay Ratio (Reverberation): Unlike sustained speech, a clap decays instantly. The system compares the peak energy to the energy 100ms–200ms later. If the ratio doesn't drop significantly (decay ratio <0.6), it is flagged as speech and ignored.
Zero Crossing Rate (ZCR): High ZCR indicates sharp, high-frequency broadband noise. Laptop microphones often apply low-pass filters that suppress this high-frequency noise. We relaxed the threshold to 0.01 so that quiet hand claps are still captured.
Signal-to-Noise Ratio (SNR): Instead of checking absolute volume, the classifier calculates the relative SNR (ratio of peak RMS to ambient background noise RMS). As long as the peak is at least 
2× louder than the background room noise, the clap triggers, enabling low-volume claps to wake the system.

3. Voice Wake Detection
When Smaran is in standby, a background thread continuously passes the audio queue to SpeechRecognition utilizing a local faster-whisper model.
It listens for specific wake phrases like "wake up" or "hey smaran".
Repetition & Noise Guards: To prevent fan noise from causing loops, the system discards phrases where a single word occupies more than 
70% of the audio energy, or single-word conversational fillers.

4. Transition & Deadlock Prevention
OS Driver Release Delay: When transitioning from calibration to background scanning, the system enforces a 1.0s sleep delay to allow the Windows driver (like Intel Smart Sound) to fully release the hardware device.
Queue Flushing: Waking up requires stopping the background listener. To prevent thread lock deadlocks, Smaran injects a dummy silent chunk into the queue, immediately releasing the background thread so it can close PyAudio before the active listening loop begins.

Smaran Vision Mode works through a real-time computer vision pipeline that maps your hand gestures to computer controls, boss:

1. **Webcam Capture & Mirroring**: The pipeline captures video frames at 30 FPS and mirrors them horizontally so that moving your hand to the right naturally moves the cursor to the right.
2. **Hand Tracking (MediaPipe)**: A custom [HandTracker] parses the video frames to track up to two hands simultaneously, identifying 21 key coordinate joints (landmarks) per hand.
3. **Gesture Classifier**: The [GestureRecognizer] calculates the Euclidean distance between fingertips to classify gestures:
   * **Single-Hand (Mouse Actions)**:
     * *Cursor Tracking*: Index finger extended.
     * *Left Click / Drag*: Thumb + Index finger touching.
     * *Right Click*: Thumb + Index + Ring fingers touching.
     * *Select (Zoom Lock)*: Thumb + Index + Middle fingers touching.
   * **Two-Hand (System Actions)**:
     * *Open Selected Item*: Spreading index fingers apart (requires Select first).
     * *Close Active Window*: Bringing index fingers together to touch (requires Select first).
   * **Exit**: Holding a closed fist for 2.0 seconds releases the camera and shuts down the mode.
4. **Cursor Smoothing & Control**: The [CursorController] translates coordinates using PyAutoGUI. It applies speed-based Exponential Moving Average (EMA) smoothing (restricted to `MAX_ALPHA = 0.10`) to eliminate cursor jitter.
5. **HUD Overlay**: An OpenCV overlay prints a real-time diagnostic panel (FPS, detected gestures, active state trackers, and control legends) directly onto your camera feed.

Vision Mode runs independently from the assistant core and can be activated or disabled as needed.

# Design Philosophy

Smaran follows a Free-First Development Philosophy.

Principles:

* Use free APIs whenever possible.
* Prefer local processing when practical.
* Use specialized agents instead of a single model.
* Separate automation from intelligence.
* Build systems that remain useful even when one component fails.
* Focus on workflow enhancement rather than chatbot-style interaction.

The goal of Smaran is not to be a chatbot.

The goal is to act as a voice-first desktop assistant that combines automation, intelligence, and computer vision into a unified system.

Intelligence Layer

Smaran uses a confidence-based routing system to determine the best agent for each query.

this is the routing architecture 
Routing Architecture
User Query:- user input message which is spoken with smaran
↓
Weighted Scoring:-the message is converted to text and keywords are searched,each agent obviously has 
certain keywords and if they are found points are alloted using python dictionaries 
↓
Confidence Evaluation:- now the agent which has highest keywords is subtracted with the agent which has 
the second highest keywords, if the gap is high the highest keyword agent wins but if gap is low 
then it falls back to groq api. groq api will go through sentence and decide who this task is going to 
be assigned to 
↓
Best Agent Selection:- based on the task the best agent among the five agents are going to be selected
↓
Response Generation:- the input given by the user the agent sees through it and finds out the best output 
and gives it back to the user in the form of text 
↓
Voice Output:- the same text is then converted to speech and responded by smaran 

entire process takes nearly 10-15 seconds at max depending on the internet speed,input given.

Vision Mode introduces computer vision capabilities.

Features:

Hand Tracking
Cursor Control
Gesture Recognition
Mouse Interaction

Smaran Vision Mode works through a real-time computer vision pipeline that maps your hand gestures to computer controls, boss:

1. **Webcam Capture & Mirroring**: The pipeline captures video frames at 30 FPS and mirrors them horizontally so that moving your hand to the right naturally moves the cursor to the right.
2. **Hand Tracking (MediaPipe)**: A custom [HandTracker] parses the video frames to track up to two hands simultaneously, identifying 21 key coordinate joints (landmarks) per hand.
3. **Gesture Classifier**: The [GestureRecognizer] calculates the Euclidean distance between fingertips to classify gestures:
   * **Single-Hand (Mouse Actions)**:
     * *Cursor Tracking*: Index finger extended.
     * *Left Click / Drag*: Thumb + Index finger touching.
     * *Right Click*: Thumb + Index + Ring fingers touching.
     * *Select (Zoom Lock)*: Thumb + Index + Middle fingers touching.
   * **Two-Hand (System Actions)**:
     * *Open Selected Item*: Spreading index fingers apart (requires Select first).
     * *Close Active Window*: Bringing index fingers together to touch (requires Select first).
   * **Exit**: Holding a closed fist for 2.0 seconds releases the camera and shuts down the mode.
4. **Cursor Smoothing & Control**: The [CursorController] translates coordinates using PyAutoGUI. It applies speed-based Exponential Moving Average (EMA) smoothing (restricted to `MAX_ALPHA = 0.10`) to eliminate cursor jitter.
5. **HUD Overlay**: An OpenCV overlay prints a real-time diagnostic panel (FPS, detected gestures, active state trackers, and control legends) directly onto your camera feed.

Vision Mode runs independently from the assistant core and can be activated or disabled as needed.

# Design Philosophy

Smaran follows a Free-First Development Philosophy.

Principles:

* Use free APIs whenever possible.
* Prefer local processing when practical.
* Use specialized agents instead of a single model.
* Separate automation from intelligence.
* Build systems that remain useful even when one component fails.
* Focus on workflow enhancement rather than chatbot-style interaction.

The goal of Smaran is not to be a chatbot.

The goal is to act as a voice-first desktop assistant that combines automation, intelligence, and computer vision into a unified system.
